# 3DP Agent — 专家路由架构实现方案

多材质(FDM/树脂/金属/环保)× 多应用(通用/液冷/牙科/珠宝)× 多模型编排。

**核心原则:**
- **计算层 = 算法 + 物理引擎**(不是 LLM):几何指标、应力/流道仿真。
- **知识层 = 专业 LLM 专家**:树脂/金属/环保各配一个领域专家。
- **编排层 = 主控 agent**:决定每个子任务派给谁、合并、裁决、出报告。
- **反馈回路**:专家返回结构化结果 → 主控交叉验证 → 分歧裁决 → 共识报告。

---

## 一、架构总览

```
[输入] STL/STEP + 材质家族(FDM/树脂/金属/环保) + 应用(通用/液冷/牙科/珠宝)
   ↓
┌─ ① 材质识别 ─────────────────────────────────────────┐
│  自动检测(几何+用户确认) → materialFamily              │
└──────────────────────────────────────────────────────┘
   ↓
┌─ ② 几何预处理(统一:单位/居中/法线/包围盒)──────────────┐
│  已存在(client/src/analysis/geometryConversion 等)     │
└──────────────────────────────────────────────────────┘
   ↓
┌─ ③ 分族指标引擎(算法,非 LLM)─────────────────────────┐
│  metrics/fdm.ts   → 悬垂/壁厚/层间/翘曲/支撑           │
│  metrics/resin.ts → 固化/吸力/孤岛/排水孔/方向          │
│  metrics/metal.ts → 热应力/残余应力/变形/锚点/除粉      │
│  metrics/eco.ts   → 湿度/降解/脆性/温度窗口             │
└──────────────────────────────────────────────────────┘
   ↓
┌─ ④ 分族评分(确定性,每族权重不同)──────────────────────┐
└──────────────────────────────────────────────────────┘
   ↓
┌─ ⑤ 专家路由(每个子任务派给最优模型)───────────────────┐
│  几何分析     → 廉价快模型(AMD Qwen3 / DeepSeek)        │
│  失败预测     → 材质专属:金属→推理强模型(Claude),       │
│                 树脂→领域模型,环保→领域模型             │
│  优化建议     → 强模型(Claude)                          │
│  可打印性评分 → 强模型 + 规则交叉                        │
│  视觉(打印照片)→ 多模态模型(后续)                       │
└──────────────────────────────────────────────────────┘
   ↓
┌─ ⑥ 应用层检查 ──────────────────────────────────────┐
│  applications/liquid-cooling.ts: 流道连通/泄漏/壁厚/散热 │
│  applications/dental.ts / jewelry.ts(树脂)             │
└──────────────────────────────────────────────────────┘
   ↓
┌─ ⑦ 共识裁决(主控) ───────────────────────────────────┐
│  专家返回 {问题,原因,概率} → 交叉验证 → 分歧裁决 →      │
│  一份共识报告 + 可执行修改(方向/支撑/排水孔/变形补偿)     │
└──────────────────────────────────────────────────────┘
```

## 二、每个材质家族的"指标引擎"(算法,不是 LLM)

### FDM(现有,保留)
- 悬垂角、最小壁厚、层间粘合、翘曲风险、支撑估算

### 树脂(Phase 1,新)
| 指标 | 算法逻辑 |
|---|---|
| 固化深度估算 | 按层高+曝光估算固化穿透,查欠固化区 |
| 孤岛检测 | 找出与主体不连的悬浮片(打印会掉) |
| 吸力风险 | 大面积横截面在抬升时的剥离力 → 建议方向 |
| 排水孔 | 检测封闭空腔 → 需要开孔位置 |
| 打印方向建议 | 最小化吸力+支撑 → 优化朝向 |

### 金属 LPBF(Phase 2,新)
| 指标 | 算法逻辑 |
|---|---|
| 热应力热点 | 厚薄突变/大面积悬挑/角部 → 残余应力风险区 |
| 变形估算 | 简化的热-力模型 → 预计哪个方向翘 |
| 支撑锚点 | 悬挑超过 45° → 该加锚的位置 |
| 除粉 | 封闭内腔 → 粉末排不出 → 需设计除粉孔 |

### 环保材料(Phase 3,新)
| 指标 | 算法逻辑 |
|---|---|
| 湿度敏感 | 材料吸湿 → 打印前干燥建议 |
| 降解窗口 | 存放/打印温度窗口 |
| 脆性/附着力 | 层间弱 → 结构风险提示 |

## 三、专家路由:每个子任务派给谁

| 子任务 | 派给 | 返回结构 |
|---|---|---|
| 几何推理(描述问题) | AMD Qwen3 / DeepSeek(廉价) | `{issues: [{type, severity, location}]}` |
| 失败预测(FDM) | DeepSeek(够用) | `{failureModes: [{mode, probability, cause}]}` |
| **失败预测(金属)** | **Claude 推理强模型**(链式因果) | `{stressHotspots, expectedDistortion, orientation}` |
| 失败预测(树脂) | 树脂领域模型 | `{suctionRisk, islandIsolation, drainNeeds}` |
| 优化建议 | Claude(强) | `{suggestions: [{action, impact, effort}]}` |
| 可打印性评分 | Claude + 规则交叉 | `{score, verdict, confidence}` |
| 视觉(打印照片) | 多模态模型(后续) | `{defectClass, severity}` |

**模型路由规则(预算感知):**
```
materialFamily === 'metal' → 失败预测用 Claude(推理型)
materialFamily === 'resin' → 用树脂领域模型
否则                  → DeepSeek(省钱)
高价值/高风险件        → 全部用强模型
```

## 四、共识裁决(主控怎么"反馈回来")

1. 各专家返回**结构化 JSON**(不是自由文本)→ 好合并、好裁决
2. 主控**交叉验证**:不同专家的判断冲突时(如金属专家说 70% 变形,规则说 40%)
   - 规则为基准,LLM 为增强 —— 冲突时**物理/规则优先**
3. **分歧裁决**:高分歧 → 再问一个强模型(批判者)仲裁
4. 输出:**共识报告 + 置信度**(每个结论标 AI/规则/物理 来源)

## 五、实施阶段

```
Phase 1(树脂):
  - metrics/resin.ts + 树脂专家 agent + UI 材质切换
  - 应用:牙科/珠宝(树脂生态)
Phase 2(金属 + 液冷):
  - metrics/metal.ts + 金属专家(Claude 推理)+ 热应力估算
  - applications/liquid-cooling.ts(流道/泄漏/散热)
Phase 3(环保 + 多模型路由完善):
  - metrics/eco.ts + 视觉模型接打印照片反馈
```

## 六、依赖的服务端配置

- `/api/llm` 目前只配了 **DeepSeek**(便宜快)。要派"Claude 推理"给金属,需在服务器加 `ANTHROPIC_API_KEY`(Vercel + .env)。
- AMD 机器(`amd-cloud`)作为"廉价快模型"来源(日常几何推理)。
- 未来的多模态:服务器加 `GEMINI_API_KEY`(看图)。

## 七、我(Claude)在架构里的角色

- **设计/编排**:我把这套路由逻辑写成代码(专家怎么选、怎么裁决)。
- **App 运行时**:路由由代码执行,不是我实时介入 —— 但**每轮的模型选择策略**由这套设计决定,我可以帮你调优。
- **跨模型整合**:视觉/金属推理等需要新模型时,我帮你接/测/调。
